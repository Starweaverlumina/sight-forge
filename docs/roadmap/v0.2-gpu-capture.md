# v0.2 milestone: GPU capture and processing

## Objective

Replace the GDI and CPU reference path with a lower-latency architecture while preserving compatibility mode and the project's accessibility safety boundary.

## Candidate capture APIs

1. **Windows Graphics Capture**
   - Modern user-consented window and monitor capture.
   - Good fit for window selection and borderless applications.
   - Requires careful handling of frame-pool resizing and device loss.

2. **Desktop Duplication API**
   - Direct3D-based output duplication.
   - Strong fit for whole-display capture and dirty-region updates.
   - Requires explicit recovery from access loss, display changes, and session transitions.

The implementation should hide either option behind an `IFrameSource` abstraction so compatibility capture remains available as a fallback.

## Processing architecture

```text
IFrameSource
    -> ID3D11Texture2D
    -> tone shader
    -> edge shader
    -> temporal motion shader
    -> magnification/crop shader
    -> WPF-compatible presentation surface
```

## Required measurements

- Capture-to-present latency
- Median and 99th-percentile frame processing time
- Dropped-frame rate
- GPU utilization
- Dedicated and shared GPU memory use
- Device-loss recovery time
- Behavior during resolution, scaling, HDR, and display changes

## Acceptance targets

Initial engineering targets, subject to hardware testing:

- 1080p processing at 60 FPS on a midrange discrete GPU
- No unbounded frame queue
- Graceful fallback to compatibility capture
- No elevated privileges
- No game-process handles beyond ordinary window discovery
- No injection, hooks, memory inspection, input automation, or anti-cheat interference

## Implementation sequence

1. Define `IFrameSource` and immutable frame metadata.
2. Move the current GDI implementation behind `CompatibilityFrameSource`.
3. Prototype Windows Graphics Capture monitor capture.
4. Keep frames on the GPU through processing and presentation.
5. Port tone correction to an HLSL compute or pixel shader.
6. Port edge enhancement.
7. Add temporal motion history textures and camera-motion suppression experiments.
8. Add device-loss and display-change recovery.
9. Benchmark against the v0.1 reference pipeline.
10. Retain a user-visible compatibility fallback.
